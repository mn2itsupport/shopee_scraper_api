Suggested reading order

The fastest path to understanding a request end-to-end. Everything below is grouped to match this order.

  1. app/main.py — the FastAPI app is built and its routers mounted here.
  2. app/routers/scrape.py — the one endpoint that matters, POST /v1/{site_key}/pdp, calling out to everything else in order.
  3. app/core/auth.py → rate_limiter.py → usage_logger.py — the three gates a request passes through.
  4. app/scrapers/registry.py → browser_pool.py → sites/shopee_br.py — how a URL becomes structured data.
  5. app/models/schemas.py — the shapes everything above passes around; worth skimming early since every other file assumes it.

Everything else (dashboard routes, the admin CLI, proxy/CAPTCHA plumbing) is safe to read on demand.

01

Entry & config

Where the process starts and where every tunable setting lives.

app/main.py

Entry point

Builds the FastAPI app, wires the browser pool's startup/shutdown into its lifespan, and mounts the three routers. Run via uvicorn app.main:app.

SymbolKindWhat it does
lifespan()async context managerCalls browser_pool.startup() before the app accepts traffic and browser_pool.shutdown() on exit — the single shared Chromium instance's life span matches the app's.
appmodule-level valueThe FastAPI instance; includes scrape.router, dashboard_api.router, dashboard_pages.router.
health()function · GET /healthReturns {"status": "ok"} — liveness probe, no auth.
Windows-specific fix

On win32, the module forces WindowsProactorEventLoopPolicy before anything else runs. uvicorn --reload's subprocess supervisor can otherwise leave the default loop as SelectorEventLoop, which cannot spawn subprocesses — and Playwright launches Chromium as one.

app/config.py

Entry point

One Settings object, populated from .env via pydantic-settings, imported everywhere a tunable is needed.

SymbolKindWhat it does
SettingsclassFields: Supabase URL/key, admin dashboard password, Playwright headless flag, concurrency/timeout/retry caps, proxy mode & credentials, default rate limit.
Settings.proxiespropertyParses proxy_list (a JSON string) into a Python list; returns [] on bad JSON instead of raising.
settingsmodule-level valueThe singleton every other module imports — from app.config import settings.
02

Shared contracts

The Pydantic shapes that let auth, scraping, storage, and the dashboard agree on data without importing each other.

app/models/schemas.py

Models

Every Pydantic model that crosses a function boundary in this app. Read this before reading anything else that passes data around.

SymbolKindWhat it does
ScrapeRequestmodelRequest body for the scrape endpoint — just url: str.
PDPDatamodelNormalized product-detail-page shape every site adapter must return. Common fields (title, price, currency, rating, sold_count, image_urls) are top-level; anything site-specific goes in the free-form raw dict, which is why adding a new site never requires a schema change.
ScrapeResponsemodelAPI response envelope: status, optional data: PDPData, optional error.
AuthedKeymodelWhat require_api_key resolves an X-API-Key header into — the key's id, its client/plan ids, and the plan's rate/quota numbers, so downstream code never re-queries the plan.

app/deps.py

Shared dep

One small lookup used by the scrape route: turn a site_key string into the sites table's row id.

SymbolKindWhat it does
get_site_id(site_key)functionLooks up sites.id by site_key, caching hits in a module-level dict so it's one DB round trip per site key for the process's lifetime. Returns None for an unknown key (the route turns that into a 404).

A site added to the DB after the process started is picked up on its first request — misses aren't cached, only hits are.

03

Database

The Supabase (Postgres) connection and the six tables everything else reads and writes.

app/db/client.py

Database

The single point every other module goes through to talk to Supabase.

SymbolKindWhat it does
get_supabase()function, @lru_cacheBuilds and caches one supabase.Client using the service-role key. The client is synchronous — every call site on the request hot path wraps it in asyncio.to_thread so it doesn't block the event loop.

app/db/schema.sql

Database

Applied once, by hand, against the Supabase project. Not a migration tool — just the DDL, plus a seed row for shopee_br.

TablePurpose
clientsOne row per subscriber (name, email).
plansA subscription tier: requests_per_minute, daily_quota, monthly_quota, duration_days, price.
api_keysLinks a client to a plan. Stores key_hash (SHA-256) and key_prefix (first 8 chars, for display) — never the raw key. status is active / suspended / expired.
sitesOne row per supported website — site_key, display_name, base_domain. Seeded with shopee_br.
usage_logsOne row per request, any outcome — status in success / failed / captcha_blocked / rate_limited / quota_exceeded. Read by both quota enforcement and the dashboard.
pdp_dataThe scraped record itself: common columns plus raw jsonb for site-specific extras. Linked to usage_logs via usage_log_id.
04

Core: auth, limits, logging

Everything the request goes through before a browser is ever touched — and the write that always happens afterward.

app/core/security.py

Core

The three pure functions that keep a raw API key from ever touching the database.

SymbolKindWhat it does
generate_api_key()functionReturns a new secret: "sk_" + secrets.token_urlsafe(32).
hash_api_key(raw_key)functionSHA-256 hex digest — this, not the raw key, is what's stored and matched on lookup.
key_prefix(raw_key)functionFirst 11 characters ("sk_" + 8), stored alongside the hash so a key is recognizable in a list without exposing it.

app/core/auth.py

Core

The FastAPI dependency every protected route depends on. Turns an X-API-Key header into an AuthedKey or raises 401/403.

SymbolKindWhat it does
require_api_key(x_api_key)async dependencyHashes the header, looks up the key (off-thread), then checks in order: exists → 401; status == "active" → else 403; expires_at in the future → else marks the row expired and 403s. Returns an AuthedKey built from the row's joined plans data.
_lookup_key(key_hash)functionThe actual (blocking) Supabase query — key row plus its plan's rate/quota numbers in one round trip via a joined select.
_mark_expired(api_key_id)functionFlips status to "expired" the first time a lapsed key is used, so later lookups short-circuit on the cheaper status check instead of re-comparing timestamps.

app/core/rate_limiter.py

Core

Two independent checks with two different lifetimes — see the module docstring for the reasoning.

SymbolKindWhat it does
check_burst_limit(api_key_id, requests_per_minute)functionPer-key deque of timestamps in a module-level dict; drops entries older than 60s, then raises 429 if the remaining count is already at the plan's cap. In-memory — resets on restart, and only correct for one process (see roadmap note in the architecture doc).
check_quota(api_key_id, daily_quota, monthly_quota)functionCounts today's and this-month's rows in usage_logs for the key; raises 429 if either cap is met. DB-backed, so it's correct across restarts.

app/core/usage_logger.py

Core

The write every single request produces, win or lose.

SymbolKindWhat it does
log_usage(api_key_id, site_id, request_url, status, response_time_ms)functionInserts one row into usage_logs, returns its new id (or None). Called from routers/scrape.py's finally block, so it runs regardless of how the scrape ended.
05

Scraper engine

Everything that turns a product URL into a browser session and, hopefully, structured data.

app/scrapers/base.py

Scraper

The contract every site adapter implements, and the two exception types the rest of the pipeline branches on.

SymbolKindWhat it does
ScraperErrorexceptionAny failure that isn't a CAPTCHA wall — bad response shape, timeout, unexpected page. Propagates straight to the route as a failed log + 500.
CaptchaBlockedErrorexceptionRaised when an adapter detects an anti-bot interstitial. This is the one exception registry.scrape_with_retries catches and retries on.
BaseScraperabstract classDeclares site_key, base_domain, and the abstract async fetch_pdp(context, url) -> PDPData. A new site = a new subclass of this + one registry entry.

app/scrapers/browser_pool.py

Scraper

One Chromium process for the whole app; a fresh, isolated BrowserContext per request, capped by a semaphore.

SymbolKindWhat it does
startup()async functionStarts Playwright, launches one headless (or not, per config) Chromium Browser, and creates the asyncio.Semaphore(max_concurrent_scrapes). Called once from main.py's lifespan.
shutdown()async functionCloses the browser and stops Playwright.
ManagedContextasync context managerOn enter: acquires a semaphore slot, asks the proxy provider for a proxy, opens a new context with a randomized UA, a fixed 1366×768 viewport, pt-BR locale, and applies the shared Stealth() instance. On exit: closes the context and releases the slot — always, even on error.
acquire_context()functionReturns a new ManagedContext — the only entry point adapters or the registry should use to get a context.
Why one shared Stealth instance

Stealth() precomputes its evasion init-script from its flags at construction time; building a new one per request would just repeat that work for every scrape.

app/scrapers/proxy_provider.py

Scraper

Pluggable source of the proxy each new browser context launches through.

SymbolKindWhat it does
ProxyProviderabstract classOne method, next_proxy() -> dict | None, returning a Playwright-shaped proxy dict.
StaticListProxyProviderclassCycles PROXY_LIST round-robin via itertools.cycle. Default mode.
RotatingSessionProxyProviderclassOne sticky gateway server; appends a fresh random session id into the username template on every call, which is how residential-proxy vendors hand out a new exit IP per request.
_parse_proxy_url(proxy_url)functionSplits http://user:pass@host:port into Playwright's separate server / username / password fields.
get_proxy_provider()function, @lru_cacheReturns the one provider instance selected by PROXY_MODE. Must stay a singleton — StaticListProxyProvider's round-robin only advances if the same itertools.cycle is reused across calls.
Don't reintroduce a per-call instance

Removing the @lru_cache (or constructing a provider directly instead of calling this) silently breaks rotation — every call would restart its own cycle at the first proxy.

app/scrapers/captcha.py

Scraper

Detection only — this file never tries to defeat a challenge, only recognize one.

SymbolKindWhat it does
is_captcha_page(page)async functionTrue if the current URL contains /verify or /challenge, or the page's HTML contains any of a small list of known anti-bot phrases (English + Portuguese). Simple text/URL matching, not fingerprinting.
CaptchaSolverabstract classOne method, async solve(page) -> bool — the extension point if a real solving service is ever wired in.
NoOpCaptchaSolverclassAlways returns False — the deliberate default. The app fails closed (captcha_blocked) rather than attempting to bypass a challenge.
get_captcha_solver()functionReturns a NoOpCaptchaSolver(). Not currently called anywhere in the retry path — registry.py retries with a fresh context instead of invoking a solver.

app/scrapers/registry.py

Scraper

Maps a site_key to its adapter and owns the CAPTCHA retry loop — the one place that changes when a second site is added.

SymbolKindWhat it does
SCRAPER_REGISTRYdict{"shopee_br": ShopeeBRScraper()} today. Adding a site is one more entry here.
get_scraper(site_key)functionDict lookup; raises KeyError on an unknown key.
scrape_with_retries(site_key, url)async functionLoops up to CAPTCHA_MAX_RETRIES + 1 attempts. Each attempt opens a brand-new acquire_context() and calls the adapter's fetch_pdp. On CaptchaBlockedError it sleeps 2 * (attempt + 1) seconds and retries with a new context (and, if configured, a new proxy); any other ScraperError re-raises immediately. After retries are exhausted, re-raises the last CAPTCHA error.

app/scrapers/sites/shopee_br.py

Adapter

The only site-specific code in the app. Implements BaseScraper for Shopee Brazil by capturing Shopee's own internal PDP JSON API call rather than scraping rendered HTML.

SymbolKindWhat it does
ShopeeBRScraper.fetch_pdp(context, url)async methodOpens a page, registers a response listener watching for URLs containing pdp/get_pc or /item/get, navigates to the product URL, checks for a CAPTCHA wall immediately and again after waiting (in 0.5s increments up to the scrape timeout) for that XHR to land. Parses the captured JSON if seen, otherwise falls back to DOM scraping.
_parse_api_response(response, url)async methodDecodes the captured response's JSON, pulls item out of data, converts Shopee's fixed-point price (divides by 100000) into a float, builds full CDN image URLs from image ids, extracts the two-part external product id from the URL's -i.<shopid>.<itemid> pattern, and returns a populated PDPData with the full raw item as raw.
_parse_dom_fallback(page, url)async methodUsed when the XHR never showed up (layout/API drift). Reads the page <title> and the og:description meta tag; returns a mostly-empty PDPData with raw={"fallback": True, ...} so a fallback response is distinguishable from a full one.
If this starts returning mostly-empty raw fields

It means Shopee's XHR shape has drifted and requests are landing in the DOM fallback. Re-inspect the live network calls Shopee's PDP page makes and adjust _parse_api_response's field mapping — the blast radius of that drift stays inside this one file.

06

Routers

The HTTP surface: one endpoint that scrapes, and a set that reads back usage.

app/routers/scrape.py

Router

The whole request pipeline in one function — auth is a dependency, everything else is called in order.

SymbolKindWhat it does
scrape_pdp(site_key, body, key)async endpoint · POST /v1/{site_key}/pdpResolves site_key to a DB id (404 if unknown) → check_burst_limit → check_quota → scrape_with_retries, timing the scrape and catching CaptchaBlockedError / ScraperError into a status string. A finally block always calls log_usage. On success, also inserts into pdp_data and returns ScrapeResponse; on failure, raises 502 (captcha) or 500.
_insert_pdp_data(site_id, usage_log_id, pdp)functionWrites the normalized PDPData into pdp_data, linked back to the usage_logs row that logged this request.

app/routers/dashboard_api.py

Router

JSON aggregates over usage_logs, feeding the Chart.js charts in dashboard.html. Every endpoint exists twice: an admin version (all clients, HTTP Basic auth) and a /me/* version (one client, scoped by their own API key, no admin password).

SymbolKindWhat it does
require_admin(credentials)dependencyHTTP Basic check against ADMIN_DASHBOARD_PASSWORD; username is ignored.
_resolve_api_key_id(raw_api_key)functionHashes a raw key from the /me/* query param and looks up its row id — the trust boundary for the client-facing dashboard.
_fetch_logs(since, api_key_id, until)functionShared query builder: usage_logs filtered by a time range and, optionally, one key.
_status_counts / _daily_counts / _monthly_counts / _kpi_countsfunctionsPure Python aggregation (via collections.Counter) over the rows _fetch_logs returns — grouping by status, by day, by month, or into today/this-month totals.
daily_stats, monthly_stats, range_stats, status_stats, kpi_statsendpoints under /v1/dashboard/stats/*Admin-only, no api_key_id filter — all clients combined.
my_daily_stats, my_monthly_stats, my_range_stats, my_status_stats, my_kpi_statsendpoints under /v1/dashboard/me/*Same aggregation functions, scoped to the key resolved from the caller's own ?api_key=.
Scaling note

Aggregation happens in Python over rows pulled from Postgres — fine at MVP log volume. If usage_logs grows large, replace the bodies of _fetch_logs/the _*_counts helpers with a Postgres view or RPC and keep the same response shapes.

app/routers/dashboard_pages.py

Router

Serves the one HTML template in two modes.

SymbolKindWhat it does
admin_dashboard(request, admin)endpoint · GET /dashboardGated by require_admin (imported from dashboard_api.py); renders dashboard.html with mode="admin".
client_dashboard(request, api_key)endpoint · GET /dashboard/meNo admin password — takes the client's own key as a query param and renders the same template with mode="client"; the template's own JS then calls the /me/* JSON endpoints with that key.

app/templates/dashboard.html

Template

Server-rendered Jinja2 page — no separate frontend build. Draws KPI tiles, a daily/monthly line chart, and a status breakdown using Chart.js (loaded from a CDN), reading its own light/dark palette off prefers-color-scheme.

Template variableSet byEffect
modedashboard_pages.py"admin" or "client" — decides the page title and which JSON endpoints (/v1/dashboard/stats/* vs /v1/dashboard/me/*) its inline JS fetches from.
api_keydashboard_pages.pyEmpty for admin mode; the client's raw key in client mode, passed back as the ?api_key= query param on every fetch.
07

Admin CLI

The manual substitute for a billing system.

scripts/manage_keys.py

CLI

An argparse tool with one subcommand per lifecycle action — run from the project root so .env resolves. A payment webhook would eventually call these same underlying functions instead of a human typing them.

Subcommand / functionWhat it does
create-plan · create_plan()Inserts a row into plans (name, rpm, daily/monthly quota, duration, price).
create-client · create_client()Inserts a row into clients (name, email).
create-key · create_key()Looks up the client and plan by email/name, generates a key, computes expires_at from the plan's duration_days, inserts into api_keys, and prints the raw key once — only its hash is ever persisted.
revoke-key · revoke_key()Sets status = "suspended" for every key matching a prefix — immediate, no grace period.
extend-key · extend_key()Adds --days onto the key's current expires_at and resets status to "active" — the renewal path.
list-keys · list_keys()Prints every key's prefix, status, expiry, and owning client/plan.
main()Builds the subparsers and dispatches to the matching args.func.
